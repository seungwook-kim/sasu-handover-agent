# 사수 (SASU) 제품 요구사항 (PRD)

- 기준일: 2026-10-11
- 기준 코드: `main` 9780da6 · 패키지 0.1.0 · Claude Code 플러그인 0.1.4
- 함께 보는 문서: [소프트웨어 설계 (SDD)](sdd.md) · [데이터 모델 (ERD)](erd.md) · [프로젝트 요약](portfolio.md)

## 1. 배경과 문제

SI 고도화·유지보수 프로젝트에서 인수인계는 보통 1주다. 문서와 말로 설명을 듣고 질문할 기회도 있지만, **무엇을 물어야 할지 모르는 채로** 기간이 끝난다. 기존 개발자가 떠난 뒤에야 처음 보는 로직과 버그를 만나고, 결국 다시 연락한다.

코드는 "무엇을 하는지"는 보여 주지만 "왜 그렇게 했는지"는 보여 주지 않는다. 그 "왜"는 떠나는 개발자의 머릿속에 있고, 인수인계 기간이 그것을 붙잡을 수 있는 유일한 때다.

| 문제 | 지금 벌어지는 일 |
| --- | --- |
| 무엇을 물을지 모른다 | 질문 목록 없이 설명만 듣고 끝난다. 정작 위험한 곳(끊어진 쿼리, 업무 코드 분기, 설정에만 있는 빈)은 묻지 못한다 |
| 받은 답이 흩어진다 | 메신저·개인 메모에 남아 코드 위치와 이어지지 않는다. 다음 담당자는 같은 질문을 다시 한다 |
| 떠난 뒤의 "왜?" | 다시 연락하거나, 추측으로 고친다. LLM에 물으면 그럴듯한 이유를 단정한다 |
| 고도화 때 원래 동작이 빠진다 | 바꾸기 전 동작을 정리해 두지 않아 "원래 되던 것"이 조용히 사라진다 |

## 2. 목표와 비목표

### 목표

| ID | 목표 |
| --- | --- |
| G1 | 인수인계 전에, 코드만 봐서는 이유를 알 수 없는 곳을 찾아 **물어볼 질문**으로 만든다 |
| G2 | 받은 답을 **코드 위치에 연결**해 두고, 다시 분석해도 지워지지 않게 한다 |
| G3 | 새 담당자의 "왜?"에 **근거와 등급([사실]/[답변]/[추정])**을 붙여 답하고, 근거가 없으면 모른다고 한다 |
| G4 | 처음 투입된 사람이 **URL → 메서드 → SQL → 테이블** 흐름과 프로젝트 구조를 바로 본다 |
| G5 | **폐쇄망 SI 현장**에서 돈다: 서버 없이, 인터넷 없이, 사내 LLM 서버로 |

### 비목표

- 코드를 고치거나 리팩터링하지 않는다. 사수는 읽고 묻고 답하는 도구다.
- 버그를 예측하지 않는다. 과거 기록 평가에서 질문 순위는 복잡도 순과 비슷한 수준이었다. 가치는 "무엇을 물을지"에 있다 ([4단계 평가](gate4-evaluation.md)).
- 실행 중인 시스템을 분석하지 않는다(로그·APM). 다른 시스템이나 즐겨찾기에서 부르는 URL은 확정하지 않고 "후보"로만 표시한다.
- 산출물 문서(설계서·정의서)를 자동으로 만들지 않는다.
- Java·Python 외 언어는 다루지 않는다.

## 3. 사용자

| 사용자 | 상황 | 바라는 것 |
| --- | --- | --- |
| 신규 투입자 (인수자) | 처음 보는 프로젝트를 1주 안에 넘겨받는다 | 무엇을 물을지, 이 화면이 어떤 테이블을 쓰는지, 이 코드가 왜 이런지 |
| 떠나는 개발자 (인계자) | 마무리 업무로 바쁘다 | 질문지에 짧은 텍스트로 답하면 끝나기 |
| PL·PM | 인수인계 진행과 고도화 범위를 관리한다 | 답변 진행률, 고도화 전 기존 동작 목록 |
| AI 에이전트 (Claude Code·Cursor) | 사용자가 레거시 코드에 대해 묻는다 | 기억 대신 확정된 근거(호출 관계·SQL·테이블·인수인계 답변)를 도구로 받기 |

## 4. 사용 시나리오

| 순간 | 흐름 | 쓰는 기능 |
| --- | --- | --- |
| S1 투입 첫날 | 분석 → 프로젝트 지도 → 궁금한 화면의 경로 추적 | `sasu index` · `sasu map` · `sasu trace` |
| S2 인수인계 1주 | 질문 만들기 → 엑셀 질문지 → 회의에서 답 적기 → 가져오기 | `sasu questions --export` · `sasu answers` |
| S3 떠난 뒤 | "왜?" 질문 → 등급 붙은 답 → 모르면 떠난 개발자에게 보낼 질문 초안 → 받은 답 기록 | `sasu ask` · `sasu draft` · `sasu answer` |
| S4 고도화 전후 | 기존 동작 목록 엑셀 → 고도화 뒤 "고도화 후 확인" 열 채우기 | `sasu behaviors --export` |
| S5 에이전트 | Claude Code에서 말로 묻기 → 에이전트가 사수 도구로 근거 수집 → 등급 붙여 답 | 플러그인(스킬 + MCP) |

모든 흐름은 웹 화면(`sasu serve`)에서도 같다.

## 5. 기능 요구사항

상태는 2026-10-11 기준이다. 모두 구현돼 있고 테스트가 있다.

| ID | 기능 | 요구 내용 | 진입점 |
| --- | --- | --- | --- |
| FR-01 | 프로젝트 분석 | Java(Spring MVC·Boot), MyBatis·iBatis XML, 매퍼 인터페이스·`@Select`, JPA, JDBC·JPQL 문자열, JSP·Thymeleaf, Python(FastAPI·Flask·Django)을 읽어 코드 그래프를 저장한다. 분석 파일은 프로젝트마다 따로 둔다 | `sasu index` |
| FR-02 | 경로 추적 | URL에서 Controller → Service → DAO → SQL → 테이블, 화면·이동 URL까지 트리로 보여 준다. 동적 쿼리 ID·저장소 밖 빈·이름으로 추정한 연결은 표시한다 | `sasu trace` · 웹 · MCP `trace_url` |
| FR-03 | 프로젝트 지도 | 기술 스택, 모듈별 URL·테이블, URL이 SQL까지 이어지는 비율, 여러 모듈이 함께 쓰는 테이블 | `sasu map` · `sasu stats` · MCP `project_overview` |
| FR-04 | 정리 후보 | 끊어진 쿼리 참조, 부르는 곳이 없는 SQL·URL·메서드·JSP. 확신 정도(높음/후보)와 사람이 남긴 근거(수정 이력)를 붙인다 | `sasu unused` · MCP `find_unused` |
| FR-05 | 공통화 진단 | 공통 코드 사용 현황, 구조가 같은 복사 코드, 중복 SQL | `sasu common` |
| FR-06 | 인수인계 질문 생성 | 9가지 신호(끊어진 쿼리, 동적 쿼리 ID, 주의 주석, 드문 업무 코드 분기, 저장소 밖 빈, 무시하는 예외, 복사한 코드, 복잡한 분기, 안 쓰는 SQL)로 질문을 만들고 영향 범위로 우선순위를 정한다. LLM 없이 규칙으로 동작한다 | `sasu questions` · MCP `handover_questions` |
| FR-07 | 엑셀 질문지 | 질문을 엑셀로 내보내고, 답을 적은 파일을 가져와 질문에 연결한다 | `sasu questions --export` · `sasu answers` · 웹 |
| FR-08 | 답 기록 | 질문 하나에 답과 답한 사람을 기록한다. 다시 분석해도 남고, 코드가 바뀌어 질문이 다시 나오지 않으면 stale로 표시한다 | `sasu answer` · 웹 · MCP `record_answer` |
| FR-09 | 질문 초안 | 떠난 개발자에게 보낼 메시지(위치·코드·질문·확인한 것)를 만든다 | `sasu draft` · 웹 |
| FR-10 | "왜?" 질의응답 | 질문에 맞는 메서드를 찾고(또는 지정하고), 근거를 모아 LLM이 근거로만 답한다 | `sasu ask` · 웹 · MCP `gather_evidence`·`search_code` |
| FR-11 | 답변 검사 | 모든 문장의 등급과 근거 번호를 코드가 검사해, 맞지 않으면 [추정]으로 낮추고 이유를 보여 준다 | FR-10 안 |
| FR-12 | 기존 동작 목록 | URL마다 처리 메서드, 화면·이동, 읽는 테이블, 쓰는 테이블(등록·수정·삭제), 업무 코드 분기, 주의 주석, 받은 답을 한 줄로 적은 엑셀 체크리스트 | `sasu behaviors` · 웹 · MCP `existing_behaviors` |
| FR-13 | 웹 화면 | 한눈에 보기·인수인계 질문·물어보기·경로 추적·정리하기 탭. `파일:줄`을 누르면 코드가 열린다. 외부 CDN을 쓰지 않는다 | `sasu serve` |
| FR-14 | 에이전트 연결 | MCP 서버(stdio, 도구 10개)와 Claude Code 플러그인(스킬 + MCP) | `sasu mcp` · `claude plugin install sasu@sasu` |
| FR-15 | 여러 프로젝트 | 분석한 프로젝트 목록과 지금 프로젝트 바꾸기. 질문과 답은 프로젝트마다 따로 둔다 | `sasu projects` · `sasu use` · MCP `list_projects` |
| FR-16 | 설치·점검 | `uv tool install`, 인터넷이 막힌 PC용 꾸러미(Python·휠·임베딩 모델), 대화형 설정, 무엇이 안 되는지와 고치는 법을 보여 주는 점검 | `sasu setup` · `sasu doctor` |
| FR-17 | 코드 원문 보기 | 파일 범위나 메서드 이름으로 원문을 읽는다 | 웹 · MCP `read_code` |
| FR-18 | 평가 도구 | 공개 프로젝트의 과거 시점을 재현해 질문 생성·검색·"왜?" 답변을 채점한다 | `sasu eval-questions` · `eval-search` · `eval-why` |

## 6. 비기능 요구사항

| ID | 항목 | 요구 내용 |

| NFR-01 | 폐쇄망 | 인터넷 없이 설치·실행된다. 오프라인 꾸러미에 Python·의존성·임베딩 모델을 넣고, 웹 화면은 CDN을 쓰지 않는다 |
| NFR-02 | 가벼움 | 서버 없는 SQLite 파일 하나. 개발 PC에서 LLM을 돌리지 않는다. eGovFrame 공통컴포넌트(Java 1,092개 파일) 분석은 몇 초 안에 끝난다 |

| NFR-04 | 근거 표시 | "왜?" 답의 모든 문장에 등급과 근거 번호가 붙는다. 근거로 답할 수 없으면 "모름"과 물어볼 질문을 낸다 |
| NFR-05 | 사람 데이터 보존 | 인수인계 질문과 답은 다시 분석해도, 분석 파일 스키마가 바뀌어도 지우지 않는다 |
| NFR-06 | 오탐 표현 | 정적 분석으로 확정할 수 없는 것(외부에서 부르는 URL, 리플렉션)은 "후보"로만 표시하고 단정하지 않는다 |
| NFR-07 | 실행 환경 | Python 3.12, Windows에서 동작한다(tree-sitter 0.26의 Windows 오류를 피해 0.25를 쓴다). Git Bash의 경로 변환도 되돌린다 |
| NFR-08 | 품질 | 기능마다 pytest 테스트를 둔다 (106개). 수치를 말하는 기능은 평가 기록을 `docs/`에 남긴다 |

## 8. 범위의 한계

- 다른 시스템·즐겨찾기에서 직접 부르는 URL과 리플렉션 호출은 정적 분석으로 알 수 없다.
- 작은 로컬 임베딩 모델은 혼자서는 약하다(벡터만 Recall@10 17%). "게시글"과 "게시물"처럼 말이 다르면 검색이 흔들린다.
- 평가는 eGovFrame 한 프로젝트로 했다. "왜?" 평가는 15문항이고, 답하는 모델과 채점 모델이 같은 계열이다.
- 실제 SI 사내 코드로는 써 보지 못했다(보안상 불가).

## 9. 남은 일

| 우선 | 할 일 | 이유 | 비고 |
| --- | --- | --- | --- |
| 1 | 주니어 개발자 사용성 시험 | 사람이 실제로 질문지·물어보기를 써서 인수인계 시간이 줄어드는지는 아직 모른다 | 사람이 필요하다 |

| 3 | 오픈 웨이트 모델로 "왜?" 평가 다시 | 현장의 사내 LLM 서버는 Claude가 아니다. 채점 편향도 줄인다 | `sasu eval-why` |
| 4 | Dockerfile 실제 빌드 | 파일은 있지만 개발 PC에 Docker가 없어 빌드해 보지 못했다 | [설치 안내](install.md#7-docker) |
| 5 | 안 쓰는 메서드 후보 정밀도 측정 | eGovFrame 75건 중 표본 6건만 확인했다 | [3단계 검증](gate3-verification.md) |
| 6 | 평가 프로젝트 넓히기 | 지금 수치는 eGovFrame 하나에서 나왔다 | iBatis 세대 프로젝트 등 |
